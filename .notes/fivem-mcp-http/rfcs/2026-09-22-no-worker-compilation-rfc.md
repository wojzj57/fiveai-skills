# RFC：FxDK 单资源 HTTP MCP 与无 Worker 编译

日期：2026-09-22。状态：无 Worker、资源内提供 HTTP MCP 的方向已由用户明确要求；本文件的具体编译、预算和验收细则待审阅。此次交付为 RFC，不表示代码已经切换。

## 1. 决策

FxDK 启动 `fivem-mcp` 资源后，资源直接提供 `http://127.0.0.1:30130/mcp`；停止资源关闭 HTTP。单包、自包含，不运行外部 Broker、编译服务或子进程，不要求 AI 调用方预编译，不创建任何编译 Worker，也不保留 Worker 模式开关。

保留 `execute_ts`：服务器资源内同步转换用户提交的 TypeScript 函数体，再通过原有 Host Tick/Client 路由执行 JavaScript。插件自身源码仍在构建时转换，运行时转换只针对 MCP 提交的片段。

这项决策接受同步编译占用所在 JS 事件循环的代价。控制查询保持独立于业务 FIFO，但不再承诺编译期间实时响应、可抢占编译或按硬期限终止编译。`Promise`、`setTimeout` 或 `setImmediate` 包装不构成 CPU 隔离。

## 2. 规范关系与替代范围

本文件为 [2026-09-21 RFC](runtime-debug-mcp-rfc.md) 的定向修订；未列出的工具、身份、FIFO、确认、安全、日志和交付契约仍由该 RFC 与 [JSON Schema](runtime-debug-mcp-contracts.json) 完整定义。不是重新启用 2026-09-20 的历史方案。

| 原条款 | 新条款 |
| --- | --- |
| §2 编译 Worker 模块及流程节点 | 同进程同步编译模块，资源拥有其生命周期 |
| §3 编译准备 5s | 保留 5000ms 数值，改为返回后的预算检查，不能硬中止 |
| §6 准备阶段、§8 函数体转换 | 保留语义，补充编译前后取消与派发前复核 |
| §8.1 全节 | 由本文件 §3–6 替代；删除 Worker 创建、通信、terminate、重建和 server bundle 禁止含编译器的要求 |
| §12 `dist/compiler.cjs` Worker 产物 | 改为 `dist/compiler-runtime.cjs` 普通服务端模块；不能作为线程入口 |
| §13 编译实机验收 | 验证同步编译正确性、延迟测量、超预算后禁止派发和停止释放 HTTP |
| §14 Worker 前置门槛、禁止同步编译 | 撤销；采用本文件明确的同步编译路线 |

当前 Schema 的 `status.compiler` 已使用 `state/version/reason`，没有 Worker 专属字段，保持不变。`COMPILER_UNAVAILABLE`、`COMPILE_FAILED`、`PREPARATION_TIMEOUT` 沿用；不添加兼容别名或第 11 个工具。实作必须同时删除探针返回中的 `workerPath/running/exits` 等旧形状，正式结果遵守 Schema。

## 3. 编译模块与加载

服务端入口负责生命周期、HTTP、任务中心；编译模块提供同步 `initialize()` 与 `compile({code})`。返回 `{javascript, sourceMap, diagnostics, elapsedMs}`，不调用 native、exports、游戏事件，不访问用户工程、安装依赖或创建线程/进程。

构建将 TypeScript 5.9.3 及编译逻辑封装成普通 CJS 模块 `dist/compiler-runtime.cjs`。资源入口在 Host Tick 获取实际 `GetResourcePath(GetCurrentResourceName())`，然后从真实绝对路径加载该模块；由普通 Node 模块作用域提供真实 `__filename/__dirname`。不得使用当前构建器硬编码的 `/fivem-mcp` 路径作为兼容方案。资源改名、包含空格的安装路径和资源停止后重启必须验证。

选择独立 CJS 文件是为明确模块作用域与构建边界，不提供线程隔离。该加载路线仍需在目标 FxDK artifact 验证；失败时先修复 bootstrap/模块作用域，不恢复 Worker、不引入桌面代理。服务端依赖不得进入客户端下载白名单。

启动时完成编译模块加载和一次小片段预热，再开放 HTTP；预热超过 5000ms 或可捕获的加载/预热异常，将编译状态设为 `faulted`，记录有限长度原因，允许 HTTP 与 Lua 能力启动。正式完整交付要求编译为 `ready`。初始化本身若一直不返回，就不能承诺 HTTP 启动期限。

保持普通模块加载缓存与资源生命周期一致；重启验收必须确认没有沿用上一代任务、统计或故障状态，不通过全局删除其他模块缓存解决。

## 4. 队首准备与执行

1. 接收请求时验证 Schema、UTF-8 代码上限 64KiB、参数及目标，按现有规则入全局 FIFO。
2. 仅在任务到达队首且编译器 ready 时开始准备；一次只转换一个片段，不创建第二条编译队列。编译前检查取消、会话状态与目标身份。
3. 在 Node 调度回调内执行纯编译，不将编译工作放入 HostWork；只有后续涉及 native 的派发跨入 Host Tick。该边界不等同于保证 FXServer 的其他活动完全不受影响。
4. 使用单调时钟测量完整准备成本：AST 检查、async 函数体包装、`transpileModule`、诊断整理、source map 和结果大小检查。ES2022、类型擦除、禁止模块导入/导出及显式 require 的原约束保留；不是强安全沙箱。
5. 返回后先检查准备预算。超过 5000ms：当前任务 `failed`，错误 `PREPARATION_TIMEOUT`、错误对象 `phase=preparing`、`execution=not_dispatched`，丢弃生成代码；终态 Task 的 phase 按原契约为 settled。编译能力转为 `faulted`，后续 TS 返回 `COMPILER_UNAVAILABLE`，Lua 可继续。恢复方式为显式重启资源，不自动反复预热。
6. 未超预算但存在语法/禁用语法诊断：`COMPILE_FAILED`，未派发，编译器保持 ready。可捕获的编译器内部异常：当前任务失败、编译器 faulted；进程崩溃或内存耗尽不在可恢复保证内。
7. 成功转换后主动让出一个事件循环轮次，再经 Host Tick 派发。让出是使已就绪的控制请求有机会运行，不是保证所有网络取消都已到达。
8. 在派发提交边界再次验证取消、会话有效期、目标与资源代际。边界前处理到的取消获胜；边界后的取消按既有已派发规则处理。执行期限从派发开始计算，不把编译时间算入 `timeoutMs`。

同步编译期间不能处理的网络请求和定时器会延后执行。因此 HTTP 等待预算、会话定时清理、停止回调也不是抢占式硬期限。事件循环恢复后依据绝对截止时间重新判断，不能因 timer 回调晚执行而把过期批准、过期会话或过期任务视为有效。

## 5. 响应性、状态与停止

保留现有请求大小、会话、队列和执行槽上限，不为去掉 Worker 扩大预算。控制请求不进入执行 FIFO；可以在任务等待异步游戏结果时执行，但同步编译时会延迟。

编译统计通过服务端诊断记录输出：编译器版本、冷启动/预热耗时、准备耗时、代码字节数、预算超限次数；不记录代码、参数或 SQL。公共 `status` 仍只使用规范 Schema，不能临时塞入未定义字段。

资源停止后拒绝新任务，清理 HTTP/SSE、socket、定时器、事件监听和任务内存。没有 Worker 需要终止。空闲或异步等待状态下维持停止后 2s 内释放端口的验收目标；若停止发生于同步编译期间，应分别记录停止请求到回调执行的延迟，以及停止回调开始到端口释放的耗时，不声称可立即打断编译。

## 6. 验收与风险

| 验证 | 判据 |
| --- | --- |
| 产物与依赖 | 发布入口无 `worker_threads`/Worker 创建、无子进程编译入口；编译模块在服务端可加载，客户端下载不含编译器 |
| 默认 FxDK 部署 | 无 worker 授权配置可启动 HTTP、初始化 MCP、执行 TS；记录真实 artifact/buildId |
| 转换正确性 | 类型注解、async/await、return、语法错误、禁用 import/require、运行异常 source map 对齐 |
| 预算语义 | 注入可控时钟证明超预算返回后不派发；不能用这个单元测试冒充真实慢编译性能 |
| 取消竞争 | 编译前取消、返回后让出期间取消、派发后取消分别符合状态机 |
| 性能证据 | 真实宿主记录冷启动，以及 1/16/64KiB 合法片段和深层语法错误输入的准备耗时；每类重复 20 次并记录中位数/最大值及并发 status 延迟 |
| 超限输入 | 超过 64KiB 在编译前拒绝；source map、JS 和内部帧仍受原预算约束 |
| 生命周期 | 改名/空格路径/重启、端口占用、停止时请求清理；没有遗留任务或编译故障状态 |

不再要求旧 G1 的 100ms 隔离判据，也不设未经测量的“零卡顿”保证。样例若超过 5000ms，预算失效保护必须正确，同时不得宣布 TS 完整验收通过；应优化编译路径或明确修订输入限额，禁止静默调大预算或恢复 Worker。

风险接受：一次同步转换可能明显延迟控制与心跳，极端输入可能使资源无响应，代码字节上限不是 CPU 硬上限。适用范围仍是可信本机开发环境，不能据此宣称可安全执行恶意代码。

替代方案：Worker 已由用户排除；调用端预编译改变自包含 MCP 契约；外部编译服务增加部署进程，均不采用。

## 7. 落地与回退

实施时同步修改编译模块、HTTP 调用链、构建入口、产物白名单、测试、README 和 gate 报告。旧 `G1_worker_isolation` 与 `G3_module_load_route` 删除，以同步转换验收替换；日志访问探测保留为独立能力验证。旧 `dist/compiler.cjs` 只能作为已知受管旧产物在发布替换时移除，不删除用户配置或未知文件。

按 [后续开发 RFC](2026-09-22-http-mcp-delivery-rfc.md) 的切片推进。本次只新增设计与审查记录，现有实现仍使用 Worker。回退到上一构建不会回滚游戏或数据库副作用；旧 Worker 构建也不能当成新“无需授权”部署契约的合格版本。
